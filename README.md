# 🚀 Ventrya — Global Solution 2026/2

**FIAP | CitizenTech | Gestão de Projetos com Azure DevOps**

## 📌 Sobre o projeto

A **Ventrya** é uma plataforma de empregabilidade jovem desenvolvida para a Global Solution 2026/2 da FIAP, com o objetivo de contribuir para a preparação e a inserção de jovens de 16 a 24 anos no mercado de trabalho.

A proposta surgiu da dificuldade enfrentada por jovens que buscam a primeira oportunidade profissional, especialmente devido à exigência de experiência prévia em processos seletivos.

A plataforma oferece desafios práticos vinculados a organizações, permitindo que os estudantes apliquem seus conhecimentos, recebam avaliações personalizadas por inteligência artificial e construam um portfólio profissional a partir das atividades desenvolvidas. Também disponibiliza entrevistas simuladas para apoiar a preparação dos estudantes para processos seletivos.

## 🎯 Objetivo

Promover o desenvolvimento de competências e ampliar as possibilidades de preparação profissional de jovens em início de carreira, utilizando a tecnologia para transformar conhecimentos em experiências práticas.

A solução está alinhada ao conceito de **CitizenTech**, ao abordar um desafio social relacionado à empregabilidade e à inclusão produtiva.

## 📋 Planejamento e gerenciamento do projeto

O planejamento e o acompanhamento do desenvolvimento foram realizados por meio do **Azure DevOps Boards**, utilizando uma estrutura hierárquica composta por quatro níveis:

- **Epics:** representam os principais módulos e objetivos do projeto.
- **Features:** agrupam as funcionalidades necessárias para atender aos objetivos de cada Epic.
- **Product Backlog Items (PBIs):** descrevem os requisitos funcionais e as histórias de usuário, com suas respectivas descrições e critérios de aceite.
- **Tasks:** detalham as atividades técnicas necessárias para a implementação dos PBIs.
- **Testes:"" testes automatizados com input e output do que é esperado que a API retorne para o user.

Essa estrutura permitiu organizar as entregas, estabelecer prioridades e acompanhar a evolução das funcionalidades ao longo do desenvolvimento.

## 📅 Organização das Sprints

O desenvolvimento foi dividido em três sprints, considerando as dependências entre os módulos e a evolução das funcionalidades.

| Sprint | Período | Principais entregas |
|---|---|---|
| **Sprint 1** | 10 a 15/11/2026 | Estrutura inicial da API, autenticação JWT, controle de acesso, organizações e desafios. |
| **Sprint 2** | 16 a 18/11/2026 | Candidaturas, submissões, regras de negócio, mensageria assíncrona e geração de feedback com IA. |
| **Sprint 3** | 18 a 19/11/2026 | Geração automática de portfólio, entrevistas simuladas, avaliações com IA e documentação. |

As atividades foram registradas e acompanhadas no Azure Boards, com atualização de seus estados conforme a conclusão das entregas.

## 🛠️ Tecnologias utilizadas

| Tecnologia | Aplicação |
|---|---|
| Java 21 e Spring Boot | Desenvolvimento da API REST |
| Spring Security e JWT | Autenticação e autorização |
| Spring Data JPA e Oracle Database | Persistência de dados |
| Spring AI e Google Gemini | Avaliações e geração de conteúdo com IA |
| RabbitMQ e CloudAMQP | Processamento assíncrono de eventos |
| Render | Hospedagem da API |
| Azure DevOps Boards | Planejamento e acompanhamento das atividades |
